# strategy-frame-problem

Structure an ambiguous challenge into a clear, actionable problem definition.

## Steps

1. **Explore** — Unpack the challenge, identify assumptions and unknowns.
2. **Stakeholders** — Map affected parties using `workflow-stakeholder-alignment` skill.
3. **Define** — Write clear problem statement using `workflow-design-brief` skill.
4. **Constrain** — Identify technical, business, design constraints.
5. **Success criteria** — Define evaluation criteria using `strategy-metrics-definition` skill.
6. **Principles** — Set decision-making principles using `strategy-design-principles` skill.
7. **Prioritize** — If multiple sub-problems, rank using `strategy-opportunity-framework` skill.

## Output

Problem definition with statement, scope, constraints, success criteria, principles, and prioritized sub-problems.
Consider following up with `strategy-strategize` or `testing-benchmark`.

## Build

Use the `figma-use` skill to materialize this as a new frame on the current page in the active Figma file, named `strategy-frame-problem — [input]`. Lay it out as a polished one-page document: an eyebrow label, bold headline, and meta line at the top; numbered sections with clear typographic hierarchy; tables for structured or comparative data; and colored status badges or callout boxes to highlight key points, severity, or priority where relevant. Build incrementally and verify the result with a screenshot before finishing.
